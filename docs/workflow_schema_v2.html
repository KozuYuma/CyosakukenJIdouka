Section 1

最終アウトプット仕様（JASRAC申告用Cueシート）

提出フォーマットの各列が「どこから来るか」「現在のアプリで自動取得できるか」を整理する。出力単位はイベント（使用）ごとなので、同一楽曲が複数回使われれば複数行になる。

● 自動取得済み ● 半自動（検索＋手動確認） ● 手動入力が必要 ● 未実装（今後対応）
列名 取得元 現状 備考
使用形態 手動入力 手動 背景BGM・オープニング・挿入歌など。NUENDOのトラック名から推測可能だが確認が必要
楽曲名 songs.song_title 自動 管理番号・BPMサフィックス除去済みの曲名
音源区分 手動入力 / mp3_files.id3_album推測 手動 CD・デジタル配信・自社制作など。現状フィールドなし
レコード会社名 master_db / MusicBrainz / Spotify 未実装 CD品番からMusicBrainzのlabel-info APIで取得可能。現状songs未保持
レコード番号 songs.cd_number / mp3_files.id3_album 半自動 MP3のID3 Albumタグ or マスターDBから補完。確認は必要
使用時間（分） nuendo_events.usage_duration 未実装 Cue CSVの「長さ」列を分・秒に分解する処理が必要
使用時間（秒） nuendo_events.usage_duration 未実装 同上。HH:MM:SS.mmm形式を変換

作詞 songs.lyricist（J-WID詳細） 半自動 「詳細取得」ボタンで役割別取得済み

テーブル関係 重要な点

出力の単位はイベント（使用ごと）

同一楽曲が3回使われるとcue_sheet_outputsは3行になる。

songs は楽曲単位の権利情報

JASRAC コード・作曲者などは songs に1回保持し、cue_sheet_outputs に複写する。

使用時間は nuendo_events から

現在の「長さ」列（HH:MM:SS.mmm）を分・秒に変換して持つ。

Section 3

アウトプット完成までのワークフロー

現在のアプリで対応しているステップと、手動作業・未実装のステップを色分けで示す。

● アプリが自動処理 ● アプリ補助＋手動確認 ● 現状ほぼ手動 ● 未実装（今後）
自動
① NUENDO Cue CSV 読み込み
Tab 1 ①にCSVをアップロード。イベント名・ファイル名・使用尺・トラック名を取込む。エンコーディング自動検出（UTF-8 / Shift-JIS）。
↓
自動
② WAVファイル一覧取得
フォルダスキャンまたはCSV。ファイル名・再生時間を取込む。任意。
自動
③ MP3ファイル一覧取得
nuendo_mp3_finder CSV をアップロード。マッチ種別＋ID3タグ（作曲者・アーティスト・アルバム）を含む。
自動
④ マスターDB CSV
社内AccessDBをCSVエクスポートして読込。曲名マッチングでJASRAC・NexTone等を補完。
↓
自動
⑤ 照合実行 → 楽曲まとめ生成
Cue CSV × WAV × MP3 を照合（完全一致→正規化→管理番号→タイトル→部分の優先度）。
イベント名単位でユニーク化した songs テーブルを生成。
MP3 ID3タグ（作曲者・アーティスト・CD番号）を自動補完。
ライブラリ管理番号（3ST-755-03 / 57A-0023 / 1AN-768_盤名_25 曲名）を自動分解。
↓
半自動
⑥ J-WID 一括自動検索
曲名でJ-WID / NexToneを自動検索。1件ヒット or 作曲者一致1件 → 自動入力。複数候補→「候補あり」マーク。
半自動
⑦ MusicBrainz パイプライン
Tab 3 で MusicBrainz / Spotify / Claude API を組合せてISRC・アーティスト・アルバムを補完。
半自動
⑧ 個別手動調査（Tab 4）
「候補あり」曲を選択。J-WID詳細取得で作曲者/作詞者/編曲者を分離取得。MusicForestリンクで手動確認。✅適用で確定。
↓
現状・手動
